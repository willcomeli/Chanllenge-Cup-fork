# 三项核心评测方法与使用说明

本文档说明 JD 解析、简历解析和人岗匹配三项核心评测的 Ground Truth、指标、运行命令和结果解释。JD详细口径见 [`JD正式流程评测方案.md`](./JD正式流程评测方案.md)，完整验收设计见 [`赛题验收测试方案.md`](./赛题验收测试方案.md)。

## 1. 通用原则

1. Ground Truth 必须由人工依据原始材料标注，不能用系统输出直接充当标签。
2. GT、预测文件、岗位池和本体使用稳定 ID 对齐并冻结版本；报告保存各输入文件 SHA-256。
3. 开发模式允许读取待复核标签，但报告只能作为开发基线；正式模式只接受完成双人复核和冲突裁决的标签。
4. 系统预测必须一次覆盖全部评测 ID。解析失败保留为空预测并计入分母，不能删除失败样本后重新计算。
5. 技能和岗位先通过冻结本体及已批准别名归一，再比较标准实体。

## 2. JD解析评测

### 2.1 当前采用的版本

JD评测统一采用第一版方案，第二版120条方案不作为当前评测入口：

- 原始测试集：`data/processed/splits/jd_test_set_100.jsonl`，共100条；其中17条内容泄漏样本已由holdout等量替换。
- 当前GT：`data/processed/evaluation/jd_result_ground_truth_100_v2.jsonl`，共100条，`result` 与正式LLM输出同构。岗位由原始JD独立初标并按核心职能归并为28类；岗位明细与词表分别为 `jd_position_ground_truth_100_v2.jsonl` 和 `jd_position_vocabulary_100_v2.json`。
- 历史种子标签：`data/processed/evaluation/jd_gold_labels.jsonl`，仅用于迁移岗位和技能初始标注。
- 预测：`data/processed/evaluation/jd_test_predictions.jsonl`。
- 正式评分程序：`src/evaluation/evaluate_llm_jd_predictions.py`。
- 正式报告：`output/evaluation/jd_evaluation_report_100_v2.json`。
- 规则对照程序：`src/evaluation/evaluate_jd_parser.py`。

正式评测调用项目的 `src.processing.llm_extract_jd_skills` 生成与GT同构的LLM结果。核心指标包含scope分类、岗位、技能和技能要求类型；职责、场景、新岗位与新技能候选作为扩展指标。规则评测命令继续保留为开发对照基线，不代表正式LLM成绩。

岗位按GT生成的28类冻结词表进行ID匹配。该词表仅用于评测运行，不替换线上图谱的14岗位体系。

核心分采用scope 10%、岗位35%、技能45%、技能要求类型10%的权重。正式通过要求CoreScore、岗位Accuracy和技能micro-F1均不低于90%，证据支持率不低于95%。职责、场景和候选发现单独报告，不并入核心分。

### 2.2 正式LLM运行

```bash
python -m src.processing.llm_extract_jd_skills \
  --input data/processed/splits/jd_test_set_100.jsonl \
  --output output/evaluation/jd_predictions_100_v2.jsonl \
  --position-vocabulary data/processed/evaluation/jd_position_vocabulary_100_v2.json \
  --split jd_test \
  --batch-size 5 \
  --no-resume \
  --verbose
```

生成预测后运行同构评分器。当前GT尚未复核，只能使用开发参数：

```bash
python -m src.evaluation.evaluate_llm_jd_predictions \
  --ground-truth data/processed/evaluation/jd_result_ground_truth_100_v2.jsonl \
  --predictions output/evaluation/jd_predictions_100_v2.jsonl \
  --test-set data/processed/splits/jd_test_set_100.jsonl \
  --output output/evaluation/jd_evaluation_report_100_v2.json \
  --allow-draft
```

完成GT裁决后删除 `--allow-draft`。下面的规则对照成绩不能作为正式LLM成绩。

### 2.3 规则对照基线

执行第一版完整流程：

```bash
python -m src.evaluation.evaluate_jd_parser \
  --test-set data/processed/splits/jd_test_set_100.jsonl \
  --labels data/processed/evaluation/jd_gold_labels.jsonl \
  --predictions-output data/processed/evaluation/jd_test_predictions.jsonl \
  --output data/processed/evaluation/jd_evaluation_report.json \
  --run-label "first-version-rule-run"
```

当前result同构GT是自动迁移草稿：岗位和技能来自原标签，要求类型、证据、职责和场景依据原始JD补充。正式验收前必须逐条双人复核并由第三人裁决。去除构图泄漏后的规则基线为岗位Accuracy 58%、技能micro-F1 77.92%、综合分67.96%，不能替代正式LLM成绩。

## 3. 简历解析评测

### 3.1 Ground Truth与预测格式

当前开发集为10份简历：

- GT：`data/evaluation/resume/resume_ground_truth_10_v1.jsonl`
- 预测：`output/evaluation/resume_predictions_10_v1.jsonl`
- 报告：`output/evaluation/resume_evaluation_report_10_v1.json`
- 原文复核裁决：`data/evaluation/resume/resume_adjudications_10_v1.json`
- 复核后报告：`output/evaluation/resume_evaluation_report_10_v2.json`

GT中的 `result` 与后端 `ParsedResumeProfile` 返回结构完全一致。多模态改造只改变输入链路，不改变
评分所需的标准输出字段。评分器同时兼容预测文件、接口的 `data.result`、任务的 `result` 和模型原始
`profile` 包装。`annotationMeta` 只记录审核状态，不参与评分。

### 3.2 核心指标

简历解析最终只记录两个内容正确性指标：技能提取 `micro-F1` 与目标岗位语义准确率。文件解析成功率和LLM完成率只表示流程成功，不等同于内容准确率。岗位允许使用经原始简历人工复核确认的语义等价名称；词表外技能必须有原文证据并写入裁决文件，不能因模型输出而自动判对。

| 指标 | 判定方法 | 综合权重 |
|---|---|---:|
| 技能micro-F1 | 本体及别名归一后按技能集合计算 | 35% |
| 经历micro-F1 | 标题包含或相似度≥0.65，并要求期间一致 | 20% |
| 目标岗位准确率 | 归一后完全匹配 | 15% |
| 姓名准确率 | 文本归一后完全匹配 | 10% |
| 学历准确率 | 归一到博士/硕士/本科/大专/高中后匹配 | 10% |
| 工作年限准确率 | 绝对误差≤0.5年 | 10% |

另外报告文件解析成功率、LLM完成率、文本输入解析成功率和视觉输入解析成功率。
`abilityProfile`、`learningSuggestions`、`resumeOptimizationSuggestions` 属于分析/建议结果，当前10份GT
没有完成可重复的人工标注，不混入“简历事实提取准确率”。`direction` 和 `completeness` 也是派生展示字段，不参与准确率计算。

### 3.3 运行

先用与在线上传接口完全相同的 `create_resume_task()` 生产链路生成预测。文字 PDF/DOCX/TXT 走文本
解析与 LLM；扫描 PDF 和图片简历走多模态 LLM：

```bash
python -m src.evaluation.generate_resume_predictions \
  --manifest data/evaluation/resume/resume_ground_truth_10_v1.jsonl \
  --output output/evaluation/resume_predictions_10_v1.jsonl \
  --require-llm
```

再评分：

```bash
python -m src.evaluation.evaluate_resume_predictions \
  --ground-truth data/evaluation/resume/resume_ground_truth_10_v1.jsonl \
  --predictions output/evaluation/resume_predictions_10_v1.jsonl \
  --ontology-dir data/evaluation/ontology \
  --output output/evaluation/resume_evaluation_report_10_v2.json \
  --threshold 0.90 \
  --allow-draft \
  --allow-pending-aliases \
  --adjudications data/evaluation/resume/resume_adjudications_10_v1.json
```

当前10份原始简历复核后的结果写入 `resume_evaluation_report_10_v2.json`：技能提取 micro-F1 为93.72%，目标岗位语义准确率为100%。

当前10份仅用于开发。正式评测应扩充到30份并完成双人标注和第三人裁决，然后删除放宽参数。

## 4. 人岗匹配评测

### 4.1 核心评测与端到端评测

核心匹配评测使用人工确认的结构化简历作为输入，只衡量匹配算法；端到端评测使用系统解析结果，额外包含OCR和简历提取误差。当前已实现核心匹配评测。

当前文件：

- 简历输入：`data/evaluation/resume/resume_ground_truth_10_v1.jsonl`
- 匹配GT：`data/evaluation/match/match_ground_truth_10_v1.jsonl`
- 冻结岗位池：`data/evaluation/match/position_pool_v1.jsonl`
- 系统完整排名：`output/evaluation/match_predictions_10_v1.jsonl`
- 评测报告：`output/evaluation/match_evaluation_report_10_v1.json`

每份GT标注唯一最佳岗位、可接受岗位集合、高/中/低匹配等级、已具备必备技能和缺失必备技能。评审制作GT时不能查看系统排名。

### 4.2 指标

| 指标 | 含义 | 诊断综合权重 |
|---|---|---:|
| Top-1 Accuracy | 第一名等于GT最佳岗位 | 30% |
| Top-3 Accuracy | 前三名至少命中一个可接受岗位 | 15% |
| NDCG@3 | 最佳及可接受岗位的前三排序质量 | 10% |
| 匹配等级Macro-F1 | 高/中/低等级分类质量 | 15% |
| 缺失技能micro-F1 | 最佳岗位必备技能缺口诊断 | 20% |
| 已匹配技能micro-F1 | 最佳岗位已覆盖技能诊断 | 10% |

MRR作为辅助排序指标，不进入综合分。开发诊断线暂定综合分80%、Top-1 80%、Top-3 90%；赛题正式硬指标仍以专家GT上的Top-1不低于90%为准。

### 4.3 运行

第一步调用真实 `_build_match_report()`，让每份简历覆盖冻结岗位池的全部岗位：

```bash
python -m src.evaluation.generate_match_predictions \
  --resume-ground-truth data/evaluation/resume/resume_ground_truth_10_v1.jsonl \
  --position-pool data/evaluation/match/position_pool_v1.jsonl \
  --output output/evaluation/match_predictions_10_v1.jsonl
```

第二步评分：

```bash
python -m src.evaluation.evaluate_match_predictions \
  --ground-truth data/evaluation/match/match_ground_truth_10_v1.jsonl \
  --predictions output/evaluation/match_predictions_10_v1.jsonl \
  --position-pool data/evaluation/match/position_pool_v1.jsonl \
  --output output/evaluation/match_evaluation_report_10_v1.json \
  --allow-draft
```

正式标签完成裁决后删除 `--allow-draft`。

## 6. 结果解释

- `formal: false`：开发成绩，不可写入正式验收结论。
- `errorCases`：逐样本错误明细，应作为下一轮修复清单。
- `groundTruthSha256`、`predictionsSha256`、`positionPoolSha256`：用于证明本次成绩对应的输入版本。
- 未达到门槛时应报告真实数值和失败类型，不能只报告接口成功率或选择性排除失败样本。
